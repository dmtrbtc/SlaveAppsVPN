# Как Slave VPN обрабатывает данные

Техническая справка по коду версии **v0.3.0**. Она описывает клиент и не заменяет политику обработки персональных данных оператора вашей подписки.

## Что хранится на устройстве

| Данные | Windows | Android |
|---|---|---|
| Настройки и выбранный узел | Файлы в каталоге данных приложения | `localStorage`, зеркало в Capacitor Preferences |
| Данные доступа к кабинету | Хранилище на основе Electron `safeStorage` | Хранилище клиента на основе `localStorage` / Preferences |
| Подписки и отдельные конфигурации | Входные данные через `safeStorage`; рабочие данные ядра отдельно | Локальное хранилище приложения и данные нативного сервиса |
| Журналы и диагностика | Локальные файлы и буферы | Буферы клиента и системные журналы Android |

Шифрование отдельных записей Windows не распространяется автоматически на весь каталог приложения. В Android локальное хранилище WebView и Preferences не следует считать защищённым аппаратным хранилищем секретов. Не передавайте другим людям каталоги приложения, резервные копии и рабочие конфигурации.

Удаление подписки, выход из кабинета и удаление приложения — разные операции. Они не означают удаления данных из резервных копий ОС, журналов или систем оператора. Для удаления аккаунта и серверных данных обращайтесь к оператору.

## Какие внешние обращения выполняются

| Назначение | Какие сведения участвуют |
|---|---|
| Получение подписки | URL и данные авторизации, если нужны; сведения клиента и идентификатор устройства при поддержке оператора |
| Личный кабинет | Введённые данные входа, токены сессии и запросы действий с аккаунтом |
| VPN-подключение | Адрес выбранного узла и параметры его конфигурации; далее трафик согласно правилам |
| DNS | Запрашиваемые доменные имена передаются выбранным и служебным резолверам |
| Обновления | Запросы к GitHub Releases и серверам загрузки файлов |
| Списки правил и геобазы | Запросы к настроенным источникам списков и обновлений |
| Проверки связи и задержки | Запросы к контрольным адресам; маршрут зависит от типа проверки |
| Определение страны узла | IP узла передаётся внешнему сервису `ipwho.is`; разрешение имени также может обращаться к DNS |

Любой внешний сервис может наблюдать IP-адрес источника своего соединения и обрабатывать запрос по собственным условиям. Клиент не определяет политику хранения данных оператора, DNS-провайдера или GitHub.

## Настройки, которыми вы управляете

- **«Определять страну узлов по IP»** включено по умолчанию в v0.3.0. Выключение прекращает внешнее обогащение списка узлов через сервис геолокации; страна определяется по названию или уже имеющимся сведениям. Оно не отключает DNS, обновления и другие сетевые обращения.
- **Маршрутизация** определяет прямые соединения и соединения через туннель. Учитывайте собственные правила и системные исключения приложений.
- **DNS-профиль и DoH-провайдер** влияют на обработку доменных имён. Для начального разрешения имён и служебных операций могут использоваться отдельные резолверы; шифрованный DNS не означает передачу каждого запроса через туннель.
- **Подписки и источники правил** обращаются к указанным адресам при обновлении. Добавляйте только источники, которым доверяете.

На Android идентификатор установки создаётся и сохраняется локально; на Windows для запросов подписки используются сведения об устройстве, предусмотренные реализацией клиента. Оператор может применять их для учёта устройств. Нельзя считать такие идентификаторы анонимными только потому, что они не содержат имени пользователя.

## Перед отправкой диагностики

Клиент скрывает распознаваемые чувствительные данные перед показом и экспортом журналов, но автоматическая обработка может не распознать нестандартный формат. Просмотрите текст вручную. Удалите ключи, UUID доступа, пароли, токены, URL подписок, данные аккаунта и адреса частной инфраструктуры.

В публичное обращение достаточно включить небольшой фрагмент вокруг ошибки. Полную конфигурацию ядра и каталог приложения отправлять не нужно. [Правила поддержки](../SUPPORT.md).
