# Android storage hydration — P0.5, второй срез

Дата: 2026-08-27. База: `main` после PR #23 (`40c4bc3`).
Ветка разработки: `codex/android-storage-hydration`.

## Причина

После установки `0.2.41-dev.sources1` первый bridge-запрос кратковременно видел
0 подписок, хотя индекс и input оставались в Capacitor Preferences. Следующий
запрос восстановил localStorage и вернул 1 подписку / 5 серверов. Данные не были
утрачены, но UI мог показать ложное пустое состояние во время готовности
нативного mirror.

В `subscription-store.ts` и Android `StorageAdapter` существовали две копии
одиночного fallback-чтения. Любой временный `null` или exception Preferences
немедленно трактовался как отсутствие данных. Параллельные чтения выполняли
дублирующие native-вызовы; запоздалое mirror-чтение не было защищено от
параллельного set/remove.

## Исправление

Оба потребителя используют чистый `createMirroredStringStore`:

- localStorage остаётся первичным и читается без native-вызова;
- при его отсутствии Preferences перечитывается с задержками 30/70/150 ms;
- параллельные чтения одного ключа делят один in-flight Promise;
- generation guard не позволяет старому mirror-результату перезаписать новый
  local set или восстановить удалённое значение;
- записи и удаления одного mirror-ключа выполняются по порядку, поэтому
  медленная best-effort запись не может завершиться после удаления;
- при успешной local-записи Preferences остаётся best-effort mirror;
- при отказе localStorage запись Preferences ожидается и проверяется;
- remove остаётся неблокирующим, как и до изменения.

Отдельно UI обрабатывает более длинное окно Android Backup: если первый список
на Android пуст, subscriptions-store выполняет тихие проверки с backoff
`0.5/1.5/3/5/10/20/30/60` секунд (около двух минут суммарно). Цикл прекращается
при появлении подписки или dispose; обычный пустой аккаунт получает не более
восьми дешёвых bridge-чтений без мигания loading/error.

Максимальная дополнительная задержка 250 ms возникает только когда localStorage
пуст и Preferences не возвращает значение. Существующие локальные значения
возвращаются синхронно без retry и без Capacitor-вызова.

## Device smoke

Проверено 2026-08-27 на Xiaomi 23117RA68G, Android 16:

- `adb install -r` обновил существующий debug-пакет с `hydration1` до
  `hydration3`; production-пакет не затрагивался;
- сразу после обновления localStorage и Preferences содержали одну и ту же
  подписку: 1 подписка, 5 серверов, 4 VLESS + 1 Hysteria2;
- при сохранённом Preferences mirror были удалены только localStorage-копии
  индекса и input. Два параллельных `subscriptions.list` вернули по одной
  подписке, после чего индекс и единственный input восстановились локально;
- оба публичных probe-входа завершились успешно, оба observer получили
  одинаковые 5 событий: 5/5 серверов доступны, активное соединение не
  прерывалось;
- проверка активного прокси прошла (56 ms в режиме `bypass`, 67 ms в режиме
  `blocked`);
- в режиме «Только заблокированное» Telegram вернул HTTP 200, YouTube — 204,
  Gemini — 200;
- после возврата исходного режима `bypass` выполнен холодный force-stop/start:
  сохранились 1 подписка и 5 серверов, ошибок AndroidRuntime и fatal libc нет;
- после проверки debug-VPN отключён, ADB forward удалён.

Во время подготовительного теста `hydration1` Preferences одного debug-пакета
сначала не были видны после переустановки, а затем появились без записи со
стороны теста. Изменение inode пакета указывает на Android restore/reset, но
точная причина не доказана. Короткий retry закрывает готовность Capacitor,
а тихий UI-backoff продолжительностью около двух минут закрывает позднее
появление данных после Android Backup.

Production-приложение осталось `0.2.41-dev.5` (code 195, прежнее время
обновления 2026-08-25 20:33:50). Release tags и канал обновления не изменяются.
